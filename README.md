# Eagle Bank — Frontend

A responsive, accessible, secure banking single-page app built for the Eagle Bank frontend application. It implements authentication, a dashboard, accounts,
transactions (with filtering / sorting / pagination), and a profile editor.


The application is running against a **fully mocked API** so works end-to-end with no backend needed.

**Demo login:** `george@eaglebank.test` / `password123`

---

## Quick start

```bash
npm install
npm run msw:init     # generates public/mockServiceWorker.js (one-time)
npm run dev          # http://localhost:5173
```

Other scripts:

```bash
npm run build        # type-check (tsc -b) + production build
npm run preview      # serve the production build locally
npm test             # run the Vitest suite once
npm run test:watch   # watch mode
npm run test:coverage
npm run lint
```

> **`npm run msw:init` matters.** Mock Service Worker intercepts network calls
> using a real Service Worker in the browser, and that worker file
> (`public/mockServiceWorker.js`) is generated by the MSW CLI rather than
> committed. Run it once after install (the `msw.workerDirectory` field in
> `package.json` keeps it in sync on future installs). Tests don't need it —
> they use MSW's Node server instead.

## Tech stack

| Concern | Choice |
| --- | --- |
| Framework | React 18 + TypeScript, bundled with Vite |
| Routing | React Router v6 (lazy-loaded routes) |
| Server state | TanStack Query v5 |
| Auth/session state | React Context |

## Key decisions (and why)

**Vite SPA instead of Next.js.** There is no real backend and no server-side data
to render — auth is client-side and the "API" is mocked in the browser. A
client-rendered SPA is the simpler, faster fit; SSR would add machinery with no
payoff here. Route-level code splitting recovers the main thing an SPA can
otherwise give up (initial bundle size).

**TanStack Query for server state, Context only for auth.** These are two
different kinds of state. Anything that comes from the API (dashboard, accounts,
transactions, profile) is *server* state — it needs caching, background
refetching, loading/error status, and invalidation, which Query gives for free.
The only truly global *client* state is "who is signed in", which lives in a
small `AuthContext`. Avoiding a general-purpose global store (Redux/Zustand)
keeps the data flow obvious.

**MSW as the mock backend.** MSW intercepts real `fetch` calls at the network
layer, so application code is written exactly as it would be against a real API —
`fetch('/api/transactions?...')` — with no mock-specific branches. The same
handlers back both the browser app and the test suite, so tests exercise the real
request/response path. An in-memory DB (seeded from JSON) lets mutations like
profile edits persist for the session.

**Tailwind CSS v4 with a design token layer.** The brief weights "design system
thinking" and accessibility. Tailwind v4 is configured via a CSS `@theme` block
in `src/styles/global.css`, which defines the token set — colours, type scale,
spacing, radii, shadows and motion easings — as CSS custom properties. Every
component composes from those tokens through Tailwind utility classes, so there
are no hard-coded values and the whole look can be rethemed by editing the
`@theme` block. Tailwind v4's zero-config approach (no `tailwind.config.js`)
keeps the design-system contract in one place alongside the rest of the styles.

**Money is stored in minor units (pence) everywhere.** Amounts are integers
(`amountMinor`, `balanceMinor`) end-to-end and only converted to a formatted
string at the very edge via `Intl.NumberFormat`. This sidesteps the classic
floating-point rounding bugs in naive money handling.

**CSS-only animations, no animation library.** Entrance/transition effects use CSS
keyframes and `transition`, and respect `prefers-reduced-motion`. This avoids a
dependency that couldn't be runtime-verified in the build environment (see the
note at the bottom) while keeping motion accessible.

**Zod schemas shared between forms and tests.** Validation rules live in one place
(`features/auth/schemas.ts`) and are reused by React Hook Form's resolver and by
unit tests, so the rules can't drift.

## Mock API

All endpoints are served from `src/mocks/handlers.ts` with a small artificial
latency so loading states are visible.

| Method | Endpoint | Notes |
| --- | --- | --- |
| POST | `/api/auth/register` | Field validation → 422 with per-field errors |
| POST | `/api/auth/login` | Wrong credentials → 401 |
| POST | `/api/auth/logout` | Invalidates the session token |
| GET | `/api/auth/me` | Rehydrates the session from a stored token |
| GET | `/api/dashboard` | Totals + recent transactions |
| GET | `/api/accounts` | List |
| GET | `/api/accounts/:id` | Single account |
| GET | `/api/transactions` | `page`, `pageSize`, `sortBy`, `sortDir`, `from`, `to`, `accountId` |
| GET | `/api/transactions/:id` | Single transaction (used by the details modal) |
| GET | `/api/profile` | Current profile |
| PUT | `/api/profile` | Persists edits in the in-memory db for the session |

Auth uses a bearer token kept in `localStorage` and attached to every request by
the API client; protected endpoints return 401 without it.

## Accessibility

- **Semantic landmarks** — `<nav>`, `<main id="main-content">`, headings in order.
- **Skip link** to jump straight to main content for keyboard users.
- **Visible focus** via a global `:focus-visible` ring; focus is never removed
  without a replacement.
- **Accessible dialog** — the transaction modal implements the WAI-ARIA dialog
  pattern: `role="dialog"`, `aria-modal`, labelled by its title, focus moves in on
  open and returns to the trigger on close, `Tab` is trapped, `Escape` and
  backdrop click close it, and background scroll is locked.
- **Forms** — every field has a real `<label>`; errors are linked with
  `aria-describedby`, announced with `role="alert"`, and invalid state is exposed
  via `aria-invalid` (not colour alone).
- **Data table** — sortable columns expose `aria-sort`; rows are keyboard
  operable; background refetches are announced through an `aria-live` region.
- **Navigation** — active links use `aria-current="page"`.
- **Motion** — all animations are disabled under `prefers-reduced-motion`.

## Performance

- **Route-level code splitting** — every page is `React.lazy`-loaded behind a
  `Suspense` fallback, so the initial download is the shell plus the first screen.
- **Vendor chunk splitting** — Vite `manualChunks` separates React, data
  (TanStack Query) and form (RHF/Zod) vendors for better long-term caching.
- **Query caching** — TanStack Query dedupes and caches requests with a 30s
  `staleTime`; paginating the transactions table keeps the previous page visible
  (`placeholderData`) instead of flashing a spinner.
- **Integer money** avoids repeated float math.
- **Font loading** — Google Fonts are `preconnect`-ed and loaded via `<link>`.
- **No heavy UI/animation dependencies.**

## Design system

The `@theme` block in `src/styles/global.css` is the single source of truth: a
green/gold/paper colour ramp with semantic aliases (`--color-text`,
`--color-surface`, `--color-positive-text`, `--color-focus-ring`, …), a 1.25
type scale, a 4px spacing scale, radii, warm shadows, and motion
easings/durations. Tailwind v4 maps these custom properties directly to utility
classes, so UI primitives in `components/ui` reference only named tokens — the
whole look can be rethemed by editing the `@theme` block. Typography pairs
Fraunces (display), Hanken Grotesk (UI) and IBM Plex Mono (money / account
numbers).

## Testing

Run with `npm test`. The suite uses Vitest + React Testing Library, with MSW's
Node server providing the same mock API the app uses (started in
`src/test/setup.ts`).

- **`features/auth/schemas.test.ts`** — Zod validation: rejects bad emails, short
  passwords, and passwords missing an uppercase letter or number; accepts valid
  input.
- **`components/ui/TextField.test.tsx`** — accessibility behaviour: label
  association, `role="alert"` + `aria-invalid` + `aria-describedby` wiring on
  error, and hint rendering.
- **`features/auth/LoginPage.test.tsx`** — integration against the mock API:
  renders the form, shows the error banner on rejected credentials, and persists a
  session token on a successful sign-in.

`src/test/renderWithProviders.tsx` wraps components in the same providers used in
production (a fresh QueryClient with retries off, a `MemoryRouter`, and the
`AuthProvider`).
